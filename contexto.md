# Current development context

The working repository is ReplayMod-Public; the Termux test copy is /sdcard/webview. Client assets are tracked. Captures, downloaded cache, encrypted credentials and logs must remain ignored.

Recent work: encrypted auth.lzk8 startup enrollment/unlock; diagnostic server/client logs; bounded recorder authentication wait; viewer module initialization fixes; configured TPS badges; compact landscape controls; synchronized player sampling and YXZ quaternion rotation playback; Share link/offline HTML with embedded modules/assets and explicit missing-asset confirmation; initial camera near a visible living player or scene part.

Legacy plaintext credential settings are no longer used, but old credential files are not automatically deleted. The unlocked process retains the decryption key; this cannot secure credentials against a compromised running machine. No full Motor6D reconstruction is implemented. Offline export tests verify module closure, embedded assets, missing-file manifest, safe payload serialization and cancellation using a simulated DOM. Actual Chrome file opening and Roblox capture behavior still require device testing.

Verification: npm run build, npm test, npm run format:check, git diff --check; browser syntax is checked as an ES module. Never treat the common-script node --check alone as verification of app.js.


Latest viewer work: collapsed Menu with Explorer and thumbnail action, FPS placement, no movement hint, English controls, shared asset cache/progress/two-attempt retry and failure-only manual retry; three attempts in offline export. R6 SpecialMesh types/CharacterMesh metadata, bundled head mesh and projected face decals, subtly beveled classic limbs, small distance-limited nameplates. Lighting now captures current/legacy style flags, atmosphere offset, clouds, local lights and Camera post effects including depth of field and color grading. Renderer uses recorded exposure/fog distances, skybox/PMREM, normal shading controls and shader-based post effects; docs/rendering.md records approximations. Browser launch was attempted using Playwright Chromium/full Chromium with software GPU configurations, but render processes terminate here; no new visual rendering approval is claimed. DOM initialization/Menu/Explorer/thumbnail placement and offline HTML generation were verified in a simulated DOM. Actual Roblox and Chrome device comparison remain required.

Screenshot follow-up: controls use touch-safe text selection; loading status can be dismissed/reopened; UI can be hidden and restored; ambient fill was calibrated brighter and an exposure multiplier added under Rendering. Simulated-DOM checks cover dismiss, reopen, retry and hide/show; real GPU/Chrome comparison is still required.

Seven Roblox references show a brighter surface and shorter shadow coverage in lower quality, with distant shadows absent. The viewer now has adjustable Near/Medium/Far shadow range around the camera; these ranges are approximations. Solid parts no longer receive the mesh fallback texture, local PBR maps are used where available, and Neon has emissive color.

Offline HTML follow-up: the offline bootstrap supplies its embedded capture directly to the viewer's selector and opens it without fetching/rebuilding the library. This is covered by the offline capture-row regression test; actual file opening in a physical browser remains required.

Current replay inspection: the 250-part test replay contains 135 distinct, valid cached OBJ MeshParts (about 100k faces total), so its missing environment is not caused by absent or unparsable mesh assets. It has no static rocks or other map geometry because the recorder previously excluded `Terrain`. New captures record an exposed-only 4-stud terrain voxel window around the player and reconstruct it in browser geometry grouped by material; older captures require a new recording. Mobile rendering now caps internal pixel ratio, skips inactive post-processing, reduces the soft-shadow map, and reuses shadows only after a meaningful scene/camera change. Studded surfaces have a procedural fallback if DDS decode fails. Physical browser validation remains required.

Local upload follow-up: Delta's local POST call reached the server but remained blocked in the executor for more than the recorder's 20-second authentication wait. The client then fell back to 3.5 KB `HttpGet` pieces (2,322 requests) and stopped around piece 1,400. Loopback uploads now select the existing localhost-only GET route immediately, use 6 KB pieces, retry each failed piece up to four times with a real panel progress bar, and write the precise failure to `replaymod-client.log`. Recorder serialization now includes `base.terrain`; server upload regression coverage verifies terrain survives chunk assembly. Actual Android executor transfer still needs retesting.

Viewer follow-up: scene menu has section labels; optional ray-based occlusion has a smaller budget and delayed hiding. Replay pose updates no longer dirty the shadow map when a shadow caster has not actually moved or rotated. Three.js frustum culling remains active independently. Dynamic face deformation is not implemented; verify head mesh/color and R6 appearance in the actual game/browser. GPU visual validation and FPS comparison remain pending.

Online viewer diagnostics are batched to the loopback-only `/api/diagnostics/viewer` endpoint and written as JSON lines to `replaymod-viewer.log` (configurable with `SERVER_WEBVIEW_VIEWER_LOG_PATH`). They capture button IDs, selected settings, aggregate rendering counters, asset failure identifiers and script error locations; input text, replay content and credentials are excluded. Batches and file size are bounded; offline viewers do not send. A server restart is required after deployment.

Viewer logs from the mobile session show peaks of about 900 draw calls, changing triangle counts with the view, and a WebGL context loss followed by restoration. These are snapshots, not controlled benchmarks. The wireframe reference makes lines behind surfaces visible; GPU frustum culling already operates, while CPU ray occlusion is optional and has a cost. The UI now consolidates Scene, Rendering, Camera, Explorer and Details in one sidebar. Shadow map resolution, update cadence and render resolution are configurable, with balanced/responsive/soft defaults. Shadow coverage now follows the camera position in texel increments at a shorter interval; physical-device validation of motion, culling and FPS is still needed.

Touch follow-up: Menu now closes the sidebar without a separate X; Camera offers locally remembered arrows or analog joystick with separate up/down buttons. Player labels are larger and use bundled Builder Sans when available. New captures include custom Sky sun/moon texture IDs and a bounded basic representation of part-attached SurfaceGui/BillboardGui text; common font families use bundled assets, while unsupported families and GUI layouts fall back or are approximated. Actual Roblox capture, touch interaction and GPU rendering remain to be verified on device. Older captures lack scene-text metadata.

Audio and Explorer follow-up: recorder observes Sound events in Workspace/SoundService with play position, volume, playback speed, loop, rolloff and optional captured part/attachment offset; events are capped at 20,000. `/api/asset/audio` serves local or permitted remote audio and offline export packs referenced sounds. Browser playback uses Web Audio spatialization and requires user interaction; SoundGroup mixing, audio graphs/effects and all server-side audio are not captured. Explorer now expands hierarchy/child instances recorded by new captures, and part property overrides remain local to the viewer across playback and seeks. Sound, editable properties and real executor behavior require device testing; old recordings cannot recover absent metadata.
